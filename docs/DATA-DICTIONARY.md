# 积分规则

会员号、事件号和消费引用均为字符串，前导零保留。积分必须正整数，使用Decimal校验后转为整数，不支持小数积分。事件时刻有时区偏移，统一UTC。规则有效窗与积分可用期均为半开区间。
同一时刻先发放，再消费，最后退款；同类按事件编号排序。消费批次按最早到期、最早发放、批次编号依次选择，余额不足时整笔失败。批次在到期时刻立即不可用，不能消费未来发放积分。
退款必须引用同一会员已成功消费，累计退款不得超过原消费。部分退款按原分配的逆序回拨，先回拨最后消耗的批次；未到期恢复，已到期只记过期退款，绝不复活。后续消费使用回拨后的可用余额。
发放积分=可用积分+已消费积分−全部已退款积分+自然到期积分+过期退款积分。已退款包括有效恢复与过期不恢复。失败消费与失败退款均不改余额，移入隔离。
期末时点默认2026-11-03T00:00:00+08:00，未来事件隔离。示例会员00001：100+80发放，消费120，退款30，其中20恢复、10过期；再消费50后剩余30。

## 跨期迟到退货

结账时点之后到达的退货不修改已发出的期末凭证，而是按裁决落到两种处理之一：

- `重开上期`：退货能追溯到同会员原消费，且原分配中仍可消费的积分足以覆盖本笔退货。处理结果是重开上期核对后回拨。
- `差额结转`：原消费已过期、可回拨积分不足或无法追溯。差额带到当前期处理，原消费关联保留在 `trace`。

单笔结果字段：`points` 退货积分、`restored` 回到当前可用的积分、`expired_refund` 因原批次已过期而记入的过期损失、`delta` 本笔对当前余额的差额（等于 `restored`）、`previous_balances` 切换前正式余额、`official_balances` 切换后正式余额、`reconcile` 对账证据、`status` 入账状态（已入账/已存在/未切换）。

约束：`restored + expired_refund = points`；同一 `run_id + 退货单号` 只入账一次；正式余额只在 `reconcile.passed` 为真时更新，否则保留 `previous_balances`；归档以正式余额为准，若正式余额无法由已通过的对账记录复算则归档状态为待复核。
